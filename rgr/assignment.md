# Расчётно-графическая работа (РГР)

## 1. Цель

Самостоятельно спроектировать и реализовать приложение на **Java Core**, демонстрирующее:

- объектно-ориентированную декомпозицию;
- использование коллекций и (при необходимости) дженериков;
- работу с файлами;
- обработку ошибок;
- хотя бы один осмысленный элемент **многопоточности**.

Допускается альтернатива: консольное Java Core-ядро + тонкий REST-слой на Spring Boot (по согласованию с преподавателем). В этом случае вместо явных потоков/`ExecutorService` достаточно корректного потокобезопасного хранилища (`ConcurrentHashMap` и т.п., как в практике 15) под конкурентными запросами — по согласованию. Реактивный/`@Async`-стек Spring в курсе не изучается и не требуется.

## 3. Общие требования к программе

1. Язык: **Java 25** (допустимо 21+). Укажите версию в README.
2. Сборка: Maven или Gradle **либо** понятная структура исходников + инструкция запуска.
3. Код разделён на пакеты/классы (не один «бог-класс»).
4. Ввод-вывод: данные читаются из файла; результат пишется в файл и/или выводится в консоль.
5. Ошибки формата входных данных обрабатываются без падения JVM (битая строка — пропуск с предупреждением в лог, разбор остальных данных продолжается).
6. README: как собрать и запустить, формат входных данных, пример; ссылка на репозиторий GitHub.
7. Многопоточность: см. требования варианта (параллельная обработка частей данных / пул задач / producer-consumer / конкурентный доступ к общему состоянию).
8. **Git / GitHub:** вести разработку в Git и публиковать проект в **личном** репозитории GitHub (не в общем студенческом репозитории курса). История коммитов должна отражать ход работы (не один коммит «всё сразу» в день сдачи).
9. **Качество кода** (перед сдачей):
   - форматирование (formatter);
   - статический анализ / стиль (linter);
   - базовые unit-тесты ключевой логики (расчёт, разбор входных данных, доменные правила — не обязательно UI/CLI целиком).

   Рекомендуемый стек и настройка: [resources/quality-tools.md](../resources/quality-tools.md) (Spotless / Checkstyle / JUnit 5 или эквивалент через IDE + Maven/Gradle).
10. **Логирование:** ключевые события и ошибки писать через logger (не только `System.out`).  
    Достаточно `java.util.logging` (JUL) из JDK **или** SLF4J + Logback / Log4j2 (удобно при Maven/Spring Boot).  
    Минимум: старт/завершение обработки, ошибки разбора входных данных, сбои в потоках. Уровни: хотя бы `INFO` и `ERROR`/`SEVERE`.
