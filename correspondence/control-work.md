# Контрольная работа (заочная форма)

## 1. Цель

Самостоятельно освоить основы Java Core в объёме практик очного курса **без** многопоточности и Spring:

- JDK, синтаксис, массивы и методы;
- ООП (классы, наследование, интерфейсы, исключения);
- дженерики, коллекции, файлы, Stream API;
- одно **интеграционное** приложение по варианту (ООП + коллекции + файлы).

Многопоточность и Spring Boot в КР **не требуются** (практики 11–16 очного курса не сдаются).

## 2. Состав КР

| Часть | Что сдавать | Вариант |
|-------|-------------|---------|
| **A** | Практики **1–10** очного курса | `(N - 1) mod 20 + 1` |
| **B** | Интеграционное задание (раздел 5) | `(N mod 10) + 1` |

`N` — номер в журнале (или по согласованию с преподавателем).  
В практике 5 дополнительно номер паттерна GoF: `(N - 1) mod 22 + 1` — как у очников.

1. Код — в личном репозитории GitHub (пакеты/папки `practice01` … `practice10` или отдельные модули).
2. К сдаче КР: **сводный** печатный (или PDF) отчёт по части A — на каждую практику кратко: номер, постановка своего варианта, скрин/фрагмент вывода, путь к коду в репо. Полные листинги всех 10 практик в бумажный отчёт тащить не обязательно, если код доступен по ссылке на GitHub.

## 4. Часть B. Интеграционное задание — общие требования

1. Язык: **Java 25** (допустимо 21+). Версию указать в README.
2. Код разделён на пакеты/классы (не один файл на всё).
3. Данные читаются из **файла**; результат — в файл и/или консоль.
4. Некорректные строки входного файла обрабатываются без падения JVM (пропуск + сообщение / счётчик ошибок).
5. Используйте коллекции (`List` / `Map` — по смыслу варианта) и обработку исключений.
6. README: как собрать и запустить, формат входных данных, пример, ссылка на GitHub.
7. **Git / GitHub:** тот же или отдельный репозиторий; история коммитов отражает ход работы.

## 5. Часть B. Варианты

### Вариант 1. Анализатор продаж

Вход: строки `date;product;qty;price` (qty — целое, price — цена за единицу).  
Функции: сумма выручки; топ-3 товара по выручке; выручка по дням; экспорт отчёта в файл.

### Вариант 2. Учёт заявок в поддержку

Заявки: id, client, topic, priority (1–5), status (`OPEN`/`DONE`).  
CLI или меню: добавить, список открытых, закрыть по id, сохранить/загрузить из файла.

### Вариант 3. Каталог фильмов

Фильмы: title, year, genre, rating.  
Загрузка из файла; поиск по жанру; средний рейтинг по жанрам; экспорт отчёта.

### Вариант 4. Склад SKU

Товары: sku, name, stock, price.  
Операции: приход/продажа (меняется stock), отчёт о дефиците (stock < порога), сохранение состояния в файл.

### Вариант 5. Группы и оценки

Строки: `student;group;subject;grade`.  
Средний балл по студенту и по группе; список должников (есть оценка < 3); экспорт отчёта.

### Вариант 6. Расписание автобусов

Рейсы: route, from, to, departTime, delayMin.  
Поиск рейсов по станции отправления; список с задержкой > 0; экспорт выборки в файл.

### Вариант 7. Очередь печати (симуляция)

Задания: id, user, pages. Очередь на `Queue` / `ArrayDeque`: добавить задание, «напечатать» следующее (убрать из очереди и дописать строку в лог-файл), показать длину очереди. Данные заданий можно загрузить из файла.

### Вариант 8. Подсчёт слов в текстах

Каталог (или список путей) `.txt`-файлов; индекс: слово → сколько раз встретилось (без учёта регистра).  
Топ-20 слов; сохранение индекса в файл.

### Вариант 9. Переводы между счетами

Счета: id, owner, balance. Перевод: from, to, amount (из файла операций).  
Запрет отрицательного баланса; итоговое состояние счетов в файл; журнал выполненных/отклонённых операций.

### Вариант 10. Метеоданные

Записи: date, temperature, humidity.  
Средняя температура по месяцам; дни с аномалией (|t − среднее_месяца| > порога); экспорт отчёта.

## 6. Пояснительная записка (часть B)

Объём ориентировочно **5–10 страниц** (Markdown или PDF), отдельно от сводного отчёта части A:

1. Титул: дисциплина, «Контрольная работа», ФИО, группа, **варианты A и B**, дата.
2. Цель и постановка интеграционного задания.
3. Проектирование: диаграмма классов (ASCII/Mermaid), краткое описание классов.
4. Структуры данных и алгоритмы.
5. Инструкция пользователя и примеры вход/выход.
6. Выводы, список источников, URL репозитория(ев).

## 7. Критерии оценки

| Критерий | Макс. баллов |
|----------|--------------|
| Часть A: практики 1–10 (полнота и работоспособность) | 50 |
| Часть B: интеграционное задание | 35 |
| Отчёты, README, GitHub | 15 |
| **Итого** | **100** |

**Зачёт по КР:** ≥ 60 баллов и успешная демонстрация/защита преподавателю.

Ориентир по части A: сданы **все 10** практик; при уважительной причине преподаватель может принять ≥ 8 из 10 с пропорциональным снижением баллов.

Штрафы: плагиат — 0; один «бог-класс» в части B — −10; нет репозитория / пустая история — −5.
