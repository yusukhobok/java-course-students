## Общая постановка

1. Подготовьте `List<Entity>` ≥ 10 элементов (хардкод или файл практики 8 того же номера).
2. **Три** конвейера Stream: фильтр+map+sort; агрегат (average/sum/count); `anyMatch`/`allMatch`.
3. `groupingBy` по полю варианта.
4. Реализуйте `Optional<Entity> findBest(...)` по критерию варианта через `max(Comparator)` или `min(Comparator)`. Для пустого списка возвращайте `Optional.empty()`. Обработайте результат способами из раздела «Требования к Optional».
5. Задача на `java.time` из таблицы.
6. `Files.lines` + Stream для файла варианта.

Циклы `for` для подготовки данных допустимы; аналитику делайте через Stream.

## Требования к Optional

На результате `findBest(...)` обязательно продемонстрируйте **все три метода `Optional`**: `map`, `orElse`, `orElseThrow`. Вызов `Stream.map` из пункта 2 не заменяет `Optional.map`.

1. **Необязательный результат для отчёта:** через `Optional.map` преобразуйте найденный объект в строку с его именем или идентификатором и значением критерия поиска. Через `orElse` задайте строку «Нет данных» для отсутствующего результата.
2. **Обязательный результат:** отдельно получите найденный объект через `orElseThrow` с поставщиком исключения, например `() -> new NoSuchElementException("Нет данных для выбора лучшего объекта")`. Для пустого списка перехватите ожидаемое исключение в демонстрационном коде и выведите его тип и сообщение, чтобы программа могла продолжить работу.
3. Проверьте оба способа на исходном списке и на отдельном пустом списке. Для непустого списка строка отчёта и объект из `orElseThrow` должны соответствовать одному и тому же результату поиска.

Не возвращайте `null` вместо `Optional` и не подменяйте требуемые методы безусловным `get()` или ветвлением через `isPresent()`.

## Состав отчёта (печатный вид)

Отчёт сдаётся **в распечатанном виде**.

1. **Титульный лист** — дисциплина «Java-программирование»; номер и название практики; ФИО, группа, **номер варианта**; дата сдачи.
2. **Постановка задачи** — условие своего варианта (для практик 1–2 — номера задач из задачника и краткая суть каждой).
3. **Ход выполнения** — как решали задачу: структура программы, важные типы/классы/методы, при необходимости блок-схема или краткий алгоритм.
4. **Листинг программы** — исходный код (весь проект или ключевые классы/методы) моноширинным шрифтом, читаемый кегль.
5. **Результаты работы** — не менее 2–3 прогонов: входные данные и полученный вывод (текст консоли или скриншоты с читаемым текстом).

Для задания на `Optional` включите в отчёт четыре результата: строку найденного объекта через `map` + `orElse`, строку «Нет данных» для пустого списка, успешное получение объекта через `orElseThrow` и тип с сообщением ожидаемого исключения для пустого списка. Кратко объясните, когда отсутствие результата допустимо, а когда выбранный сценарий требует исключения.

На защите дополнительно демонстрируется **работающая программа** (исходники + запуск).
