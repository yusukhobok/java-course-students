## Общая постановка

1. Создайте текстовый файл данных варианта (≥ 10 строк, свой формат из таблицы; тот же файл можно переиспользовать в практике 10, где действует тот же минимум).
2. Прочитайте в `List<Entity>` (класс сущности с полями варианта). Битые строки — пропуск + сообщение.
3. Постройте `Map<K, List<Entity>>` группировки.
4. Постройте `Set` уникальных значений указанного поля; сравните с размером списка.
5. Выведите топ-3 по критерию сортировки варианта (`Comparator`).
6. Выполните задания раздела «Стандартные функциональные интерфейсы» на прочитанном списке.

## Стандартные функциональные интерфейсы

Используйте класс `Entity` своего варианта из таблицы и материал раздела 4.8 [лекции 4](../lectures/04-exceptions-generics-collections/lecture.md) (основы лямбд — раздел 3.4 [лекции 3](../lectures/03-oop-advanced/lecture.md)). В объявлениях подставьте конкретное имя класса вместо `Entity`.

1. Объявите `Predicate<Entity>` для отбора объектов, числовое поле из столбца «Топ-3 по» которых превышает заданный порог. Реализуйте его лямбдой и примените к списку для двух порогов; один должен дать пустой результат.
2. Объявите `Function<Entity, String>` и реализуйте лямбдой преобразование объекта в строку отчёта с его идентификатором (или именем) и значением выбранного числового поля. Объявите `Consumer<String>` через ссылку на метод `System.out::println`. Выведите строки для отобранных объектов, вызывая `apply` и `accept`.
3. Создайте универсальный интерфейс `Calculation<T>` с аннотацией `@FunctionalInterface` и методом `double calculate(T value)`. Реализуйте `Calculation<Entity>` лямбдой, извлекающей выбранное числовое поле. Напишите обобщённый метод `<T> double sum(List<T> values, Calculation<T> calculation)` и вычислите сумму для исходного и отобранного списков. Для пустого списка результат должен быть 0.
4. Реализуйте `Comparator<Entity>` из общей постановки лямбдой или через `Comparator.comparingInt` / `comparingDouble` со ссылкой на метод получения поля. Соблюдайте направление сортировки своего варианта.

Обработку выполняйте обычными циклами и методами коллекций; Stream API изучается в практике 10. Все объявленные функциональные интерфейсы должны использоваться в программе.

## Состав отчёта (печатный вид)

Отчёт сдаётся **в распечатанном виде**.

1. **Титульный лист** — дисциплина «Java-программирование»; номер и название практики; ФИО, группа, **номер варианта**; дата сдачи.
2. **Постановка задачи** — условие своего варианта (для практик 1–2 — номера задач из задачника и краткая суть каждой).
3. **Ход выполнения** — как решали задачу: структура программы, важные типы/классы/методы, при необходимости блок-схема или краткий алгоритм.
4. **Листинг программы** — исходный код (весь проект или ключевые классы/методы) моноширинным шрифтом, читаемый кегль.
5. **Результаты работы** — не менее 2–3 прогонов: входные данные и полученный вывод (текст консоли или скриншоты с читаемым текстом).

В отчёте объясните параметры типов `Predicate<Entity>`, `Function<Entity, String>`, `Consumer<String>` и `Calculation<T>`. Покажите отбор для двух порогов, печать через ссылку на метод, суммы для исходного и отобранного списков и топ-3 в заданном порядке.

На защите дополнительно демонстрируется **работающая программа** (исходники + запуск).
