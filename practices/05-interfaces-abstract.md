## Общая постановка

1. Абстрактный базовый класс варианта с общим состоянием и абстрактным методом расчёта.
2. Три конкретных наследника с разной формулой расчёта.
3. Два интерфейса-роли (имена в таблице); реализуйте их в наследниках.
4. Сервисный класс, работающий с массивами интерфейсных типов (полиморфно): агрегирует расчёт и печатает отчёты.
5. `default`-метод в одном из интерфейсов.
6. Выполните задания раздела «Функциональные интерфейсы и лямбды» на объектах своего варианта.

## Функциональные интерфейсы и лямбды

1. Создайте собственный функциональный интерфейс `Calculation` с аннотацией `@FunctionalInterface` и методом, принимающим объект базового класса варианта и возвращающим `double`. Например, для варианта 1: `double calculate(Employee employee)`. Если метод расчёта требует аргументы (`price(units)`, `tax(amount)`, `aggregate(values)`), подготовьте одинаковые входные данные для всех объектов.
2. Реализуйте `Calculation` двумя способами: анонимным классом и лямбдой. Обе реализации должны вызывать метод расчёта объекта. Передайте каждую в сервисный метод, принимающий массив объектов и `Calculation` и вычисляющий сумму результатов. Покажите совпадение сумм; сервис должен вызывать переданную реализацию, а не напрямую метод расчёта.
3. Создайте функциональный интерфейс `Selection` с методом, принимающим объект базового класса варианта и возвращающим `boolean` (например, `boolean test(Employee employee)`). Реализуйте его лямбдой для отбора объектов, результат расчёта которых превышает заданный порог. Лямбда должна захватывать локальную переменную порога. Покажите отбор и печать для двух разных порогов, создавая отдельную реализацию для каждого. Объясните в отчёте правило `effectively final` для захваченной переменной.
4. Создайте метод `void printReport()` без параметров в сервисном классе, печатающий отчёт по подготовленным объектам. Присвойте ссылку на этот метод переменной `Runnable` (например, `Runnable report = service::printReport`) и вызовите `report.run()`. Запускать отдельный поток не требуется.

Для обработки массива используйте обычные циклы. Все объявленные функциональные интерфейсы должны использоваться в работающей программе.

## Состав отчёта (печатный вид)

Отчёт сдаётся **в распечатанном виде**.

1. **Титульный лист** — дисциплина «Java-программирование»; номер и название практики; ФИО, группа, **номер варианта**; дата сдачи.
2. **Постановка задачи** — условие своего варианта.
3. **Ход выполнения** — структура программы, важные типы/классы/методы; почему `Calculation` и `Selection` являются функциональными интерфейсами; сравнение анонимного класса и лямбды; объяснение захвата порога (`effectively final`) и ссылки на метод.
4. **Листинг программы** — исходный код (весь проект или ключевые классы/методы) моноширинным шрифтом, читаемый кегль.
5. **Результаты работы** — не менее 2–3 прогонов: входные данные и полученный вывод (текст консоли или скриншоты с читаемым текстом). Покажите совпадение сумм для анонимного класса и лямбды, а также результаты отбора и печати для двух порогов; среди них должен быть случай с пустым результатом отбора.

На защите дополнительно демонстрируется **работающая программа** (исходники + запуск).
